# Remember and recall

Finish the startup reads in [notes.md](notes.md), including the allowed index, even for a one-line request.
Save preferences, lasting facts and confirmed guidance that should change later work in this workspace.
Do not save secrets, full conversations, guesses or temporary task progress.
Link a project fact to its source instead of copying material already clear there.
Search the allowed index for the same fact and update its entry instead of making a duplicate.
Use a requested valid name, `answer-length` for answer length, or `response-language` for language.

For a personal save, show the exact proposed body, header values and workspace-relative filename, then ask to save them.
Wait for acceptance before creating the folder, note or index, and complete the ignore checks in [notes.md](notes.md) before writing.
If a reply says “yes” but no exact wording and file were offered, offer them now and wait; do not save your earlier reply as the note.
Use earlier acceptance only for that wording and file; if either changed, ask again.
For shared material, save only what the user asked to retain or [learning.md](learning.md) permits as a candidate.
After writing, read the saved entry and index separately, check that they agree, then tell the user the filename and what was saved.
Do not claim a refused or incomplete write succeeded.

In a fresh personal session, read the personal index and its active preference entries before answering, including general preferences such as answer length.
Apply preferences only in their stated context and when they fit the current request; do not apply personal preferences to shared work.
Read local evidence before relying on a changing fact and use the problem recheck rules in [notes.md](notes.md).
Mention missing or conflicting notes only when they affect the answer; a newer date alone does not settle a conflict.

For a correction, change the wrong claim, date and source, with a short reason; for problem rechecks, preserve the original claim and append the result instead.
Read [learning.md](learning.md) if the correction should help later tasks.
Ask before changing personal material unless the user accepted that exact correction and file.
Read back the entry and index and say which file changed.

For “forget”, find the note in the allowed folder and resolve an ambiguous match before deleting.
Remove its entry, index line and copies you created in that folder; check that folder for remaining references and correct them.
Keep cited source documents unless the user also asked to delete them.
Report files removed and any known copy you could not remove.
Do not claim to erase earlier conversations or backups, or restore a forgotten note from an old summary.
