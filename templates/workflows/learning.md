# Learn from corrections

Finish the startup reads in [notes.md](notes.md) before recording or reviewing lessons.
For a reusable shared correction, write or update a `lesson` entry with status `candidate` in the same turn.
Do not turn a request for this task alone into lasting guidance.
For personal corrections, follow [memory.md](memory.md)'s acceptance step; save in the accepting turn and say when nothing has been saved.
Record the mistake, correction, reason, when it applies and how to check it next time.
Record each distinct occurrence with its date and local evidence or user-statement reference.
Do not count a repeated description or a copied report as another occurrence.
Read the saved entry and index separately and tell the user the filename.
Use the correction for the current task; do not apply a candidate as standing guidance later.

On the second distinct occurrence, update the same candidate and propose procedure steps and a check.
Wait for acceptance of that exact proposal before changing its type, status or standing rules.

For “review what you learned”, read the allowed index and relevant lessons separately.
Make no file changes during review, including dates, indexes and review reports.
Give at most five numbered one-line proposals, each with entry name, action, reason and exact change.
Use `promote`, `expire` or `write as procedure`; prefer a procedure for two distinct occurrences.
If a change needs more than one line, offer a separate preview and leave it unaccepted.
If nothing merits a change, say so and give no proposals.

Change only the individual proposals the user accepts.
Reread the entry before applying an accepted proposal; stop if it changed since review.
To promote, set status to `active` and keep the evidence and limits.
To expire, set status to `expired`, move the entry to `archive/` and remove its index line.
For a procedure, revise the same entry to type `procedure` and status `active`, keeping the occurrence evidence.
Update the date and index, read both saved files separately, and report the filename.
Keep rejected and unmentioned proposals unchanged.
Do not change instruction files, permissions or tool settings, schedule reviews or continue after the session ends.
