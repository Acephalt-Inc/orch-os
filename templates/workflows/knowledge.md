# Keep a knowledge library

Finish the startup reads in [notes.md](notes.md) before using the library.
Use permitted workspace files; do not connect to an external system, fetch a remote source or upload material.
For an outside source, ask for an allowed copy inside the workspace.
Keep source documents intact unless the user asks to edit, move or delete them.

Before new research, search the allowed index for the topic and likely alternate words.
Read each matching entry separately, then its cited local files; do not gather notes through a workspace search.
If entries answer the question, use them and do not repeat the research.
If none match, name the index checked and say no relevant entry was found.

To add a source, read the file and create a `source` entry with its title, stated date or `unknown`, relative filename and section.
Describe what the source says without calling it verified fact.
To register research, read the finished file and its cited local sources, then create a `research` entry with one conclusion and a link to the full result.
Record the research date, source dates, sections, checks, limits and open questions; label missing evidence.
Update a matching entry instead of making a duplicate; add no standing instructions or lookup reminders.
Use [memory.md](memory.md)'s acceptance step for personal entries.
Write the entry and index, read each back separately, and report the entry filename.

In an answer based on an entry, include: `entry <relative filename>, dated <date>; source <relative filename>, dated <date or unknown>, section <heading>`.
Name the entry's relevant section too if it has one; otherwise say `entry body`.
Recheck a source if its age or changed contents could affect the answer; state what remains unsettled.
