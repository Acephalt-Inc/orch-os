# Role routing

Use the host's available roles and tools. These are task classes, not promises about a model's quality or cost. Record requested and observed model/effort when the host exposes them. If a consequential choice is substituted and untested, pause that branch. Keep all worker work inside the same user task and budget.

| Role | Use | Output | Instructions |
|---|---|---|---|
| [Reader](agents/reader.md) | bounded source extraction | cited facts, gaps and conflicting evidence | read-only, no children |
| [Mechanical](agents/mechanical.md) | exact specified local edit | changed paths and before/after check | named paths, no new design decision |
| [Builder](agents/builder.md) | settled implementation | artifact, tests, errors and limits | owned files, one bounded attempt unless approved |
| [Verifier](agents/verifier.md) | independent check of another author's output | supported, broken or unverified per criterion | may not author the reviewed artifact |
| [Advisor](agents/advisor.md) | one hard judgment from provided evidence | choice, uncertainty and falsifying observation | no implementation or permission grant |

Give these instructions to the worker; check its actual permissions separately.

Use direct work for a short single step. Use separate reader tasks for independent sources only if the host supports safe context selection. Never route a personal record into a firm or unrelated work context. Do not select or create a personal store through this guide. Give a child explicit authorized references, not the whole conversation. Report a missing model or meter; do not guess. Do not switch accounts or buy access to satisfy a route.
