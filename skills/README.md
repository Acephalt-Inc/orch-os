# ORCH-os skill pack (draft)

Status: **draft, not released.** Not yet installed by any command; see "Installing"
below for the planned `orch init --claude` behaviour.

These are agent skills for running a team of CLI coding agents with ORCH-os: what to do
when the human leaves, returns or goes to sleep, how to fan one goal out, how to merge
safely, how to keep research and decisions findable. Each skill is one folder with a
`SKILL.md` (YAML frontmatter `name` + `description`, then the procedure) in the format
Claude Code loads from `.claude/skills/<name>/SKILL.md`. Other agent CLIs can read the
same files as plain Markdown.

They use ORCH-os primitives (`orch msg`, `orch mailbox`, `orch task`, `orch worker`,
`orch merge-gate`, `orch mem`, `orch load`) and keep their own state under
`$ORCH_HOME` (default `~/.orch`).

## The skills

| Skill | Use it when | State it keeps |
|---|---|---|
| `away` | the human leaves and the team keeps working | `$ORCH_HOME/away.json` |
| `back` | the human returns: one delta report and the queued decisions | reads `away.json`, archives it |
| `sleep` | everything stops for the night; the morning restarts from a snapshot | `$ORCH_HOME/sleep.json` |
| `caffeine` | the machine must stay awake while the team works unattended | `$ORCH_HOME/caffeine.pid` |
| `night-shift` | overnight work limited to reversible, zero-cost tasks | `$ORCH_HOME/night.json` |
| `insight` | reading material: teach it, then add only insight that survives a test | a pointer in `orch mem` |
| `research-library` | research that must stay findable: a fixed folder contract plus an index | `$ORCH_HOME/research/` |
| `record` | writing a durable trace of a decision, finding or incident | — |
| `progress` | percent complete per project, from milestones with evidence | `$ORCH_HOME/progress.json` |
| `orch-swarm` | one goal as parallel work: task graph, routing, evidence-based acceptance | `orch task` claims |
| `full-throttle` | every worker busy: the lead writes briefs, workers decompose and pull | `orch task` claims |
| `serial-merge` | merging: one PR at a time, gate first, re-check after each | — |
| `orch-advisor` | a worker is stuck: a read-only diagnosis by the strongest model, then falsify by running | `$ORCH_HOME/advisor/` |
| `product-demo-storyboard` | planning a 30–60 second product demo video | — |

Pairs: `away` ↔ `back`; `sleep` ↔ the morning `/orch-lead-boot`; `caffeine` usually
runs with `away` or `night-shift`; `insight` feeds `research-library`; `orch-swarm`
escalates to `orch-advisor`; `full-throttle` merges through `serial-merge`.

`orch-swarm` contains one section marked `OPTIONAL SECTION — pending a wording
decision`. It can be deleted as a block (from the opening marker to `END OPTIONAL`)
without breaking the rest of the skill.

## Installing (planned: `orch init --claude --skills`)

`orch init --claude` (branch `feat/init-claude-wiring`, not yet on main) already wires Claude
Code to ORCH-os: a `SessionStart` hook in `settings.json`, the script it runs, and an
`/orch-lead-boot` slash command, all under `./.claude/` (or `~/.claude/` with
`--user`). It is idempotent, backs up `settings.json` before the first write, and
`--remove` touches only files that still carry its marker. The skill pack extends that
command with the same rules; no code for it exists yet.

### Proposed interface

```
orch init --claude [--user] --skills [all|NAME,NAME...] [--skills-prefix PREFIX] [--force-skills]
orch init --claude [--user] --remove
```

| Flag | Meaning |
|---|---|
| `--skills` | also install skills; no value or `all` = every folder in `skills/`; a comma list = only those |
| `--skills-prefix orch-` | install as `.claude/skills/orch-away/` etc. and rewrite the frontmatter `name` to match, for users who already have a skill with the same name |
| `--force-skills` | overwrite an installed copy that the user has edited (it is backed up first) |

Without `--skills`, `orch init --claude` behaves exactly as it does today: skills are
opt-in.

### What it writes

For each selected skill, `skills/<name>/` is copied to `<claude-dir>/skills/<name>/`
(`./.claude` or `~/.claude`) with a sidecar file next to `SKILL.md`:

```
.claude/skills/away/SKILL.md          # byte-identical copy of skills/away/SKILL.md
.claude/skills/away/.orch-skill.json  # {"marker": "generated by `orch init --claude`",
                                      #  "source": "orch-os@<version>", "files": {"SKILL.md": "<sha256>", ...}}
```

The sidecar, rather than a comment inside `SKILL.md`, carries the ownership marker. The
installed skill stays byte-identical to the repo copy, and a user's edit shows up as a
hash mismatch instead of going unnoticed.

### Rules (same safety model as the existing `--claude` wiring)

| Situation at `<claude-dir>/skills/<name>/` | Install | `--remove` |
|---|---|---|
| does not exist | copy + sidecar | — |
| ours, hashes match, same version | nothing (idempotent re-run) | delete the folder |
| ours, hashes match, older version | replace with the new version | delete the folder |
| ours, but a file's hash differs (user edited it) | keep, report `SKIPPED (edited)`; `--force-skills` backs it up to `<name>.orch-backup/` then replaces it | keep, report `KEPT (edited)` |
| exists without a sidecar (the user's own skill) | never touched; report `SKIPPED (not ours)`, suggest `--skills-prefix` | never touched |

Everything else in `.claude/` (other skills, `settings.json` keys, commands) is left
untouched, as today. `orch doctor` gains a `claude skills` row: installed N,
edited M, skipped K, per location (project, user).

### Packaging

`package.json` `files` gains `"skills/"`, and the installer resolves the folder like
`CLAUDE_TEMPLATE_DIR` does today
(`new URL("../skills/", import.meta.url)`).

### Tests the implementing change should add

- Fresh install writes every selected skill plus its sidecar; a second run changes no
  bytes.
- A pre-existing folder without a sidecar is untouched (bytes compared) and reported.
- An edited installed file is kept on install and on `--remove`; `--force-skills`
  backs it up first.
- `--skills-prefix` installs under the prefixed folder, and its frontmatter `name`
  matches the folder.
- `--remove` deletes only unedited folders we installed and leaves the hook-wiring
  behaviour unchanged.
- Every `skills/*/SKILL.md` has frontmatter with `name` equal to its folder and a
  non-empty `description`.
