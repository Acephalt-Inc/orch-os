## 3. Contract v1 — freeze this entire section

Copy this section byte-for-byte to `docs/private-store-contract-2.md`; hash it before implementation. There are 12 acceptance rows with one behaviour clause per row. Add `// K2.nn` at the actual assertions. Freeze the prerequisite combined decoder/admission contract digest too; contract changes stop for refreezing.

Dispatch clarification: amended binding stop 3 below specifies directory creation, lock work, transaction staging and explicit recovery separately from canonical-state replacement. Refusal or DEADLINE can leave objects created by this operation. Never describe those outcomes as zero disk effects. Builders must follow the frozen permissions and must not amend semantics during build, fix or review.

API: `readSnapshot(binding, codec, budget, projector)`, `commitSnapshot(binding, codec, expectedGeneration, value, budget)`, `mutateSnapshot(binding, codec, expectedGeneration, budget, reducer)`, `recoverSnapshot(binding, codec, budget)`. Codec is a trusted imported object with `decode(JsonValue): T` and `encode(T): JsonValue`, not a name selected from input. Validate encoded output by decoding it before disk mutation. Projector is synchronous trusted code; compute and serialize its bounded result under the same lock as the read. A default projector returns metadata, not the whole snapshot. A content-producing consumer has to supply its own trusted eligibility/serialization code. Reducer is synchronous trusted code receiving the current decoded value or absence under lock and returning the next value; validate it before publication, without returning the internal snapshot through the output cap. `commitSnapshot` uses that same mutation path, not a second protocol. The library itself prints nothing.

Projector/reducer also receive immutable command-known context `{generation,committedAt}` (generation 0 and committedAt null for absence), enabling a lifecycle consumer to check clock rollback and current generation without another read. It is not a caller-supplied policy object. Run the overall-budget check after these synchronous callbacks too.

Expected generation is a non-negative safe integer. A read returns `{status:"read",generation,output}` where output is the completely serialized bounded Buffer, or the tagged absent result. If read-lock release fails or the budget expires before return, refuse without a content result and leave the lock for explicit recovery. Amendment (MAIN 2026-10-14 22:5x, r4): if a read-lock removal was submitted before expiry and completes after expiry, the read refuses without content and reports the observed released lock; no lock is recreated. Recovery returns `{status:"recovered",generation,discardedTemps,lockReleased,warnings}` after safe cleanup; lock-release failure uses LOCK_LEFT. Failure before cleanup finishes is unavailable/recovery-required, not a recovered result. Tests K2.03/05/09/11 cover these read/recovery outcome branches in addition to writes.

Codec encode/decode must validate their complete input shape, including unknown fields; encoding is not permission to discard invalid keys. Before JSON serialization reject non-JSON values, cycles, undefined, non-finite numbers and unsafe integers rather than let JSON.stringify silently omit/coerce them. Canonical encoding orders object keys by code-point order, preserves array order and serializes numbers with JSON's finite-number spelling; feature hash computation uses the same encoder.

Persistent files are `state.json`, `.lock/` (empty cooperating mutex), and `.state-<lowercase UUID v4>.tmp`. No journal, hard-link publication, append log, backup, HEAD/object archive or automatic migration. Envelope exact fields: `{format:1, namespace, workspaceDigest, generation, committedAt, payload}`. Namespace and 64-lowercase-hex digest must match the binding; generation is a positive safe integer; committedAt is round-trippable UTC ISO milliseconds set by command clock; payload is accepted only by the imported codec. A missing partition/state gives `{status:"absent",generation:0}`. Present corruption, wrong binding or I/O error gives fixed CORRUPT_STATE/IO_UNAVAILABLE, not empty state. Do not preserve unrecognized decoded keys by spreading objects.

Limits: state including newline ≤16 MiB UTF-8; sum of regular managed state/temp bytes ≤32 MiB including the proposed new temp; directory enumeration ≤32 entries. Iterate a directory handle up to entry 33 rather than materializing an unbounded readdir result. Reject unknown entries and unsafe temps rather than delete them. Parser depth 8, array length 1,000, object keys 32, decoded string 256 KiB, with codec-specific lower field limits. Projected serialized output ≤64 KiB including framing; reject an oversized complete result, do not emit partial JSON. Cap equality passes, cap + 1 refuses. The existing state and new temp can fit exactly 32 MiB; quota arithmetic uses safe integers and inspected sizes, then counts actual written bytes.

Reads of an existing partition and writes acquire the same mkdir `.lock` mutex. Missing-partition reads first return absent without creation. Lock wait ≤2,000 ms and ≤remaining overall 5,000-ms budget; monotonic checks before retry and after wakeup. A present lock, including an interrupted owner, is not stolen by PID, age, timeout or a force flag. Hold it through state validation, projection/serialization or commit outcome. Only the holder removes its own empty lock with non-recursive removal. Recheck actual state and expectedGeneration after acquisition. Generation 0 is solely absent initial state; mutations increment once and refuse safe-integer overflow.
Capture the lock directory's dev/ino after this operation's mkdir succeeds, and capture the temp's dev/ino by fstat immediately after exclusive open succeeds, before writing. Check the budget around those awaits. If a creation returns after expiry, record its known effect and close an opened handle only; do not start the identity check or cleanup. Recheck identity before permitted removal while budget remains. An unverifiable object stays for explicit recovery. These checks are observations within the stated same-account boundary, not protection against ancestor replacement.

Commit phase matrix is normative:

| Phase / fault | Result and disk treatment |
|---|---|
| Binding/input/codec/expected generation refused | Validate binding, input, codec output and expected-generation domain before preparing folders. Compare actual generation under the acquired lock. Refuse without state replacement or temp publication; an acquired own lock may be released before expiry under amended stop 3. Preserve unrelated entries and disclose any retained lock. |
| Existing .lock, recognized leftover temp or unknown entry | LOCK_HELD / RECOVERY_REQUIRED / UNSAFE_PATH; no state replacement, temp write or temp deletion. Only the prescribed lock attempts and release of this operation's own empty lock are permitted before expiry. Never release a pre-existing lock. Reads do not clean leftovers. |
| Exclusive temp creation, write, file sync or close fails before rename | IO_UNAVAILABLE; canonical state remains unchanged, including genuine prior absence. Successful exclusive creation and captured dev/ino authorize cleanup of only that same temp before expiry, followed by release of this operation's own empty lock. EEXIST authorizes no unlink of the collision. If identity verification, cleanup or the budget prevents completion, retain the remaining objects and report LOCK_LEFT when the lock remains. No refused result claims zero disk effects. |
| Rename rejects | Await the rejection. Classified errno set: ENOENT, ENOTDIR, EACCES, EPERM, EXDEV, EINVAL, EISDIR, ENOTEMPTY, EBUSY, EROFS, EIO, ENOSPC. Any other errno stops for advice. If budget remains, submit lstat(state.json) and compare its dev/ino to the captured temp identity. Equality means written despite error. Mismatch plus one of the first ten errnos means IO_UNAVAILABLE/not installed; clean only the identity-confirmed own temp and own empty lock while budget remains. Mismatch with EIO/ENOSPC, or a failed lstat, means uncertain/WRITE_OUTCOME_UNKNOWN with no temp cleanup or lock release. | Directory open/sync/close, post-install inventory inspection or lock removal fails after successful rename | Written metadata result with durability/inventory/cleanup flags and fixed warnings; current generation remains authoritative. Emit the applicable warnings together. |
| Deadline passes after successful rename | Written metadata result, durability unverified and lockReleased false if remaining steps were skipped; start no cleanup/flush after expiry. |

Await rename and every submitted inode check. Late successful rename is known written. A rejected rename without an inode witness because the budget expired is uncertain, not DEADLINE, IO_UNAVAILABLE or written. If lstat was submitted before expiry and returns afterward, use its returned identity evidence for the classification above, then start no further filesystem work except close on this operation's handles. Thus a late confirming match is written with skipped-step warnings; a late definite mismatch is IO_UNAVAILABLE with unremoved temp/lock retained and LOCK_LEFT reported. A failed inode check is uncertain. Completion itself is known because nothing is raced; installation may remain unknown. Retain the owned lock on uncertainty and require explicit inspection/recovery before retry.

After successful rename, before releasing the lock, inspect the admitted partition by opendir listing plus lstat per entry under lock: inventoryVerified is true exactly when entries are state.json (regular file, nlink 1, current uid, mode 0600 without special bits) and .lock (this holder's empty directory). That read-only check sets `inventoryVerified`; a fault or deadline makes it false. This fixed check belongs to the transaction implementation, not an arbitrary cleanup callback supplied by a feature. Later lifecycle consumers use it before acknowledging managed-copy deletion.

Write result exact fields: `{status:"written",generation,durability:"synced"|"unverified",inventoryVerified:boolean,lockReleased:boolean,warnings:[...]}`. `durability:"synced"` means “fsync calls on the file and its folder returned without error” (K2.09; advisor Q53). It does not establish power-loss survival. Warning codes are `DIRECTORY_NOT_FLUSHED`, `INVENTORY_UNVERIFIED`, `LOCK_LEFT`; deterministic order is directory, inventory, lock. Every uncertain rename returns exactly {status:"uncertain",code:"WRITE_OUTCOME_UNKNOWN",lockReleased:false,warnings:["LOCK_LEFT"]}, with no generation, content or success claim; a passed budget does not change that tag. Non-written fixed errors after lock acquisition also carry lockReleased and warnings metadata: warnings is ["LOCK_LEFT"] if the owned lock remains, otherwise []. These are card-2 outcome fields wrapping the predecessor's fixed error; do not change the accepted admission error type, codes or messages. An error means no acknowledged state replacement; it does not mean no directory, lock or staging effects. A future CLI may map a known-written receipt to exit 0; this library card introduces no CLI exit mapping. No claim of stdout emptiness after delivery failure.

Recovery is an explicit trusted API, not silent read/write repair. It acquires the ordinary lock; a leftover lock first needs manual removal after the operator has established that no cooperating operation is active. Recovery does not determine that fact from PID/age (K2.05/11). Check admitted paths and exact entry inventory, validate canonical committed state with the real codec, discard safe recognized temp files, and return current generation or genuine absence. For each entry use lstat and exact regexp `^\.state-[0-9a-f-]{36}\.tmp$`; unlink requires isFile, nlink 1, current uid and mode 0600 without special bits. Check the complete bounded inventory before deleting: anything else yields UNSAFE_PATH and no deletion (K2.11). Observe at most entry 33 with opendir; do not materialize an unbounded list. Do not promote a temp, reset corrupt canonical state, roll back to a previous snapshot, or remove unknown entries. A failure keeps recovery incomplete. A commit refuses a residual temp and a read refuses content from such a partition (K2.11). This prevents unacknowledged staged bytes from being mistaken for committed state; it is not restoration from power loss.
